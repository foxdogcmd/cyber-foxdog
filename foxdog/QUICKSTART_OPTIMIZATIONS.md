# 🚀 Foxdog 优化快速指南

## 已实施优化（立即生效）

### 1️⃣ 智能健康监控 🏥
**问题**: 远程服务挂了，系统傻等50分钟  
**解决**: 自动检测，连续3次失败就告警

**你会看到**:
```
⚠️ 远程服务 critical: 连续 3 次失败 (EOF)

建议操作:
1. 检查靶机网络/平台公告
2. 联系管理员
3. 切换备用靶机

按 Ctrl+C 中断或继续等待
```

### 2️⃣ 智能去重 🧹
**问题**: 38个 intent，很多在重复验证同一件事  
**解决**: Planner 强制去重，同类验证≤2次

**规则**:
- 初期: 3-4个并发探索
- 中期: 2-3个聚焦验证  
- 后期: 1个远程 + 1个备用
- 本地成功后不再重复验证

### 3️⃣ 外部阻塞识别 🚫
**问题**: 多个 worker 都卡在连不上远程  
**解决**: Spectator 自动识别并暂停相关 intent

**效果**:
- 检测到批量失败 → 写入高优先级控制指令
- 如果 spectator 同时给出 `close_intents`，Coordinator 会优雅关闭对应 intent
- 黑板写入建议 → 后续 worker 优先本地验证

## 使用方法

### 零配置使用
```bash
# 正常运行即可，优化自动生效
python -m foxdog solve "题目描述" --target host:port
```

### 查看健康状态
运行中关注 coordinator 的 SwarmNote；健康监控和 spectator 阻塞都会写入黑板控制指令。

### 手动干预
如果看到 critical/dead 告警：
1. **检查**: 平台公告/Discord/网络
2. **切换**: 有备用靶机就换目标
3. **等待**: 没有就继续等，已自动降频

## 技术说明

### 健康状态分级
| 状态 | 触发条件 | 行为 |
|------|---------|------|
| healthy | 正常 | 每分钟检查 |
| degraded | 偶发失败 | 继续监控 |
| **critical** | **连续3次失败** | **告警 + 降频** |
| **dead** | **15分钟内5次失败** | **建议人工介入** |

### 自动策略调整
1. Critical 状态 → 探测频率: 1分钟 → 5分钟
2. 黑板写入指令 → Planner 看到 → 暂停远程 intent
3. Worker 优先认领本地验证任务

### 去重机制
```python
# Planner 必须对照
- 已完成 intent 的 goal/category/technique
- 在跑 intent 的方向
- deadend 中已排除的方向

# 只有新证据才派发新 intent
```
